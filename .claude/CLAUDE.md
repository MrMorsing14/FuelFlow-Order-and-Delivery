# FuelFlow

FuelFlow is a portfolio project: an order and delivery backend for a Danish heating oil and diesel supplier, built with .NET 10, ASP.NET Core Web API, EF Core and PostgreSQL, with a Blazor WebAssembly UI. The solution follows a simple layered architecture (Domain, Application, Infrastructure, Api, Web) where dependencies only point inward. Business rules live in the Domain layer and are covered by unit tests; API behaviour, authorization and database concurrency are covered by integration tests against real Postgres using Testcontainers. Never add MediatR, AutoMapper or FluentAssertions. Always use the injected TimeProvider instead of DateTime.Now, keep all prices as decimal, and return errors as ProblemDetails. Every change must keep `dotnet format --verify-no-changes`, `dotnet build -c Release` and `dotnet test` green, and new code comes with tests in the same commit. I'm coming from Java/Spring Boot and want to understand the code, so explain non-obvious .NET concepts briefly, work in small steps, and ask before making large or structural changes.
